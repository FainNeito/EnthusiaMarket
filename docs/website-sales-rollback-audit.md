# Offline shop history outbox inventory

The opt-in archive can write version-3 and version-4 shop-history outbox records. Earlier Market versions understand only version 1 and can quarantine newer records. Do not start an older plugin while version-2, version-3 or version-4 records, temporary files, corrupt files, or unexplained entries may still need recovery.

1. Stop the server through its normal approved process and verify that all writers are stopped. Create and independently verify an offline backup of the database and the complete Market data directory, including `history-outbox`.
2. Run `python scripts/audit-shop-history-outbox.py <offline-snapshot-history-outbox>` on a private copy. The script opens regular files read-only, validates checksums and recording-ID filenames, conservatively parses known version-1/2/3/4 payload structure, and reports aggregate counts. Unknown versions are identified by header only. It does not print transaction contents or change files. A nonempty or ambiguous inventory returns exit code 2 and requires investigation. An empty inventory returns exit code 0 only to mean no directory entries were observed.
3. If newer pending records exist, preserve the backup and use the newer compatible Market build to replay them against the correct database under a separately reviewed, controlled recovery procedure. Confirm receipt idempotency and an empty, quiescent outbox before considering any downgrade. Preserve and investigate temporary or corrupt files; never discard or rewrite them merely to make the audit pass.

This inventory checks known-format structure conservatively; it cannot establish transaction validity or fully interpret unknown future formats. It cannot prove that the server was stopped, detect every filesystem race, verify database integrity, prove migrations are backward compatible, or establish safe rollback. Missing directories, I/O errors, a symlinked snapshot directory or pending entry, and changes detected during scanning fail closed. Parent-directory symlinks and platform-specific races are not independently ruled out; audit a trusted private copy. Do not apply it to a live database or outbox; production actions require separate authorization.

Verification: `python -m unittest discover -s scripts/tests -p test_audit_shop_history_outbox.py` uses temporary fixtures and checks version classification, checksum/name failures, symlink handling, changed-directory detection and preservation of bytes. Local/hosted execution evidence is recorded separately; native recovery rehearsal remains open.
